# Weekly Review

Fifteen minutes that make the next week obvious. Honest, not cheerful.

## Read first

- Everything in `content/` dated in the last 7 days — the filenames start with dates
- `context/goals.md` — the North Star and the suggestion pool
- `context/gtm.md` — what we said we'd be doing (skip if it's still empty)

## Steps

1. List what got made this week. Just the list, by name, with dates. Seeing it written out is half the value of this skill.

2. Say in one sentence whether the North Star moved. If it didn't, say that. A week where nothing moved is worth naming — that's how the next week gets fixed.

3. Ask the owner two questions, one at a time:
   - "What actually happened out there this week — any leads, sales, replies?" (you can't see their inbox or their till)
   - "What did you not get to that's bugging you?"

4. Take their answers and update the files:
   - Anything they wish they'd done → the suggestion pool in `context/goals.md`
   - Anything you learned about the business, a price, or a customer → the matching `context/` file
   - Anything that worked → note it in `context/gtm.md` so next week does more of it

5. Name **three things for next week**. Same rule as `good-morning`: each finishable, each tied to the North Star. Put them at the bottom of the review.

6. If the week produced nothing, don't pad it. Say "quiet week" and give the owner the smallest possible first move for Monday.

## Save it

`content/YYYY-MM-DD-weekly-review.md` — the list, the honest read, and next week's three things.

## Done when

- Every file made this week is named in the review.
- The `context/` files were updated with whatever the owner told you.
- Next week's three things are written down.
